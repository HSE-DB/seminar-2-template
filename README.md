# Семинар 2: E/R-диаграммы

Создайте четыре E/R-диаграммы в **PlantUML** в файлах папки `src/`.
Пример синтаксиса: [example.puml](example.puml).
Условия заданий приведены ниже и продублированы в комментариях соответствующих `.puml`-файлов.
Источник требований — этот README.

## Как выполнить и сдать

1. Откройте свой репозиторий задания на GitHub и скопируйте его URL из меню **Code → HTTPS**.
   Подставьте его вместо `<URL_ВАШЕГО_РЕПОЗИТОРИЯ>` и выполните:

   ```bash
   git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> seminar-2
   cd seminar-2
   git switch -c seminar-2-solution
   ```

2. Выполните задания в четырёх файлах `src/`, указанных ниже. Проверьте, что диаграммы отображаются в PlantUML.
3. Сохраните изменения и отправьте ветку на GitHub:

   ```bash
   git add src/
   git commit -m "Выполнен семинар 2"
   git push -u origin seminar-2-solution
   ```

4. В своём репозитории на GitHub откройте **Pull requests → New pull request**.
   Выберите `base: main` и `compare: seminar-2-solution`, нажмите **Create pull request**.
   Назовите PR «Семинар 2» и оставьте его открытым для проверки преподавателем.

   Дополнительно: PR можно создать из терминала вместо сайта. Установите [GitHub CLI (`gh`)](https://cli.github.com/),
   затем в папке репозитория выполните:

   ```bash
   gh auth login
   gh pr create --base main --head seminar-2-solution --title "Семинар 2" --body "Решения заданий находятся в src/."
   ```

   `gh auth login` нужен при первом входе в GitHub CLI. Команда `gh pr create` создаст PR и выведет ссылку на него.
   Достаточно одного способа: через сайт или через CLI.

## Задача 1: Библиотечная система

Нарисуйте E/R-диаграмму по следующим требованиям. Укажите атрибуты, ключи сущностей и кратности связей.
Связи показывайте между сущностями; внешние ключи как отдельные атрибуты добавлять не нужно.

В библиотеке хранятся книги (издания). Для каждого издания известны уникальный ISBN, название, автор, год издания
и количество страниц. Каждое издание выпускается одним издательством, у которого есть название и адрес.
В библиотеке могут храниться несколько экземпляров одного издания. Для каждого экземпляра записываются номер копии
и положение на полке. Номер копии уникален только в пределах своего издания: у разных изданий номера могут совпадать.
Книги относятся к одной или нескольким категориям. У каждой категории есть название; она может быть подкатегорией
одной другой категории.

В библиотеке зарегистрированы читатели. Для каждого читателя хранятся уникальный идентификатор, имя, фамилия,
адрес и дата рождения. Читатели берут экземпляры книг на определённый срок. При каждой выдаче записываются дата выдачи,
планируемая дата возврата и фактическая дата возврата, если экземпляр уже возвращён. Нужно хранить историю выдач,
в том числе повторных выдач одного экземпляра тому же читателю.

**Файл для выполнения:** `src/library.puml`

## Задача 2: Моделирование отношений

Нарисуйте E/R-диаграммы с указанием кратностей связей. Используйте только сущности из условий, без атрибутов.

### Адреса

- Квартира находится в одном доме.
- Дом расположен на одной улице.
- Улица находится в одном городе.
- Город находится в одной стране.

**Файл для выполнения:** `src/relationships_address.puml`

### Спортивные матчи

- В системе хранится информация о матчах, командах и арбитрах.
- Каждый матч проходит между двумя разными командами под руководством одного арбитра.
- Команда может участвовать в неограниченном числе матчей.
- Арбитр может судить разные матчи.

**Файл для выполнения:** `src/relationships_match.puml`

### Родственные связи

- У каждого человека есть два биологических родителя: отец (мужчина) и мать (женщина).
- У человека может быть несколько детей или не быть детей.
- Роли отца и матери должны быть различимы на диаграмме.

**Файл для выполнения:** `src/relationships_parents.puml`
